# StoryLex 前端对接指南

本文以当前代码为准。全部实际方法和路径见[路由清单](实际路由清单.md)，详细字段见[接口设计](../data/StoryLex%20后端接口设计与开发路线.md)。

## 连接、认证与错误

开发地址示例：`http://192.168.30.97:5000`。除注册、登录、健康检查之外，所有接口发送 `Authorization: Bearer <token>`。

```json
{"code":200,"msg":"success","data":{}}
```

必须检查响应体 `code`，不能只看 HTTP 状态：当前统一错误封装通常仍返回 HTTP 200，业务错误可能为400/401/404/405/413/500。401引导重新登录；400展示msg并保留用户可修正的输入；不要自动无限重试500。

AI生成还必须检查 `data.status`：HTTP/业务200可能表示任务已处理，但模型失败，status=failed时读取error_code、error，不允许保存。真实Key只放后端，前端只持有账号Token。

JSON请求使用 `Content-Type: application/json`；TXT上传使用浏览器FormData，不手写multipart的Content-Type，否则缺少boundary会导致上传失败。

## 三种练习必须分开

| 流程 | 出题/提交标识 | 行为 |
|---|---|---|
| 正式新学 | group_id、question_id、request_id | 每词至少答对一次或点熟，全部通过才结算；新词次日零点进入复习 |
| 正式复习 | group_id、question_id、request_id | 每词本次只答一次；推进/回退阶段；每词每日最多计一次正式复习 |
| 阅读测验 | session_id、逐题question_id、request_id | 一次提交全部题目，错词入正式复习，但保护已掌握/暂停词 |
| 收藏夹/小结自主练习 | session_id、逐题question_id、request_id | 一次提交全部题目，仅算临时成绩，不改正式状态、排程或数量 |

正式学习的选项使用 `options[].trans`，自主练习的选项使用 `options[].text`，阅读测验仍使用 `options[].trans`。自主练习用 `question_type` 和 `prompt` 区分方向；中选英题不额外暴露英文词或音标。

### 正式新学的界面顺序

1. GET题组，使用实际total作为分母，不硬编码10。group_id为null且total=0时显示今日目标完成或暂无可学词。
2. 展示一道未通过题。提交group_id、该词word_id和question_id、request_id、selected_key；看答案传is_show_answer=true且selected_key=null。
3. 用响应展开解析。答错时保留retry_question的新question_id和选项，加入本轮错词重测队列；前端决定“下一词”和重测的展示顺序。
4. 进度以后端passed_count为准；组内点熟传group_id。每个词通过后不要再以新请求作答。
5. 全部通过才调用组结算；展示summary_list。重复结算会返回原小结。
6. 重新GET下一组；最后一组允许不足10词。跨北京时间午夜，未完成旧组需要重新获取，不能继续旧组结算。

正式复习中 `passed=true, skipped=true` 表示暂停等原因无需再答，不等于答对，不能将它累计到今日复习数。使用看板reviewed_today或组结果reviewed_count。复习答题接口每词只接受一次；错误答案或查看答案也会立即记入今日复习并按服务端排程。`POST /api/words/review/complete` 只读取小组回执，不增加今日复习数；响应包含 `summary_list`，逐词给出 `is_correct`、`is_skipped`、`performance`、`selected_text`、`correct_text` 和 `word_detail`，用于展示复习小结。暂停等跳过词会标记 `is_skipped=true`，不会算作答对或答错。

## 重试和版本控制

- request_id由客户端生成；同一次操作重试必须保留请求内容和编号，新的操作换新编号。不要每次网络重试都生成新编号。
- 正式新学答错后question_id改变，重测属于新作答；必须用新question_id和request_id，不再提交旧版本。
- 自主/阅读测验先收集所有题的选择，再一次性提交；允许原答案重试，不允许改答案覆盖已结算成绩。
- 复习状态三类修改共享request_id空间；迟到的旧恢复请求只返回原回执，不撤销后续暂停。完成后重新查当前状态。
- 单词`favorite/toggle`是真正反转，不具备重试幂等性。发送后按钮禁用，遇到未知网络结果先查询收藏列表再决定，不直接重发。文章收藏则是明确设置true/false，可幂等重试。
- 阅读位置和草稿编辑使用version。先GET最新数据；保存成功更新本地version。冲突时重新拉取，让用户选择是否覆盖，不无条件丢弃新版本。

## 阅读、草稿与渲染

- 阅读位置progress为0～100数值，position为去除word标签后的正文字符偏移。跨语言字符串索引要统一按Unicode字符处理（例如JavaScript可用Array.from计算），不要使用HTML长度或滚动像素替代。
- 打开、滚动、离开正文时由前端保存位置。读取详情本身不算最近阅读。progress=100仍不算完读，需用户点击“完成阅读”。
- 继续阅读last_story只包含保存过位置、尚未手动完读、仍可访问的文章；无记录为null。
- 使用内嵌word标签和embedded_words/词表关联。仅解释允许的word节点，用安全文本节点渲染正文；不要直接将服务器或用户编辑正文作为任意HTML执行。
- 词表提供translation_book_id/title及is_out_of_book；显示当前词书标签/超纲状态，不假设每个词都有当前词书释义。
- AI预览必须等status=ready；PUT保存编辑，POST/save才入正式文库。TXT复用相同草稿接口，source_type=imported。
- 草稿只支持原词word标签，编辑不能增加目标词之外的ID；至少保留一词。TXT的source_content是原始中文，processed_content是最终混排正文，original_content预览值则为混排正文去标签后的文本，三者不要混用。
- 混排唯一词数embedded_word_count用于词表数量，embedded_occurrences是标签出现次数；不能因某词出现三次就显示三条词表。

## 文库与个人数据

scope=mine表示本人文章加收藏的系统文章；scope=recommended为内置推荐；默认all兼容全部可访问。category为all/imported/ai_generated/favorites；与source_type、keyword同时存在时取交集。

个人total_learned_words为全局有学习记录词数，total_mastered_words是其中已掌握子集；词书进度只按该词书范围统计。切换词书不重置今日数量、学习、阅读和收藏。暂停不等于已掌握；显示is_review_paused。

前端退出登录可清理本地Token；当前没有服务端Token撤销/刷新接口，不能据此承诺远程强制下线。离线编辑队列、发音音频、端侧布局等范围见[验收报告](完整流程验收报告.md)。
